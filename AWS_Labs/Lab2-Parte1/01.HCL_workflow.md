# HCL - TERRAFORM WORKFLOW

## BASIC STRUCTURE

[Terraform Workflow Documentation](https://developer.hashicorp.com/terraform/intro/core-workflow)


>The core Terraform workflow has three steps:

- Write - Author infrastructure as code.
- Plan - Preview changes before applying.
- Apply - Provision reproducible infrastructure.

## INDIVIDUAL WORK

### WRITE

- You write as a regular code.
- You use a versioning tool.

```Python
# Write initial config
$ vim main.tf

# Initialize Terraform
$ terraform init

Initializing provider plugins...
# ...
Terraform has been successfully initialized!

```

- With time and practice you get to know the syntax better. Your config is coming together as you expected.

```Python
# Make edits to config
$ vim main.tf

# Review plan
$ terraform plan

# Make additional edits, and repeat
$ vim main.tf

```

- There is a useful feedback loop between editing code and running test commands.

### PLAN

>When the feedback loop pays off, it's time to commit your work and review the final plan.

```Python
$ git add main.tf
$ git commit -m 'Managing infrastructure as code!'

[main (root-commit) f735520] Managing infrastructure as code!
 1 file changed, 1 insertion(+)
```

Because `terraform apply` will display a plan for confirmation before proceeding to change any infrastructure, that's the command you run for final review.

```Python
$ terraform apply

An execution plan has been generated and is shown below.
# ...
```

### APPLY

>It's time to get things done.

- After one last check, you can use Terraform to provision real infrastructure.

```Python
Do you want to perform these actions?

  Terraform will perform the actions described above.
  Only 'yes' will be accepted to approve.
  Enter a value: yes

# ...

Apply complete! Resources: 1 added, 0 changed, 0 destroyed.

```

- At this point, you do your version control stuff

```
git remote add origin https://github.com/*user*/*repo*.git
git push origin main
```

>This core workflow is a loop; the next time you want to make changes, you start the process over from the beginning.

Notice how closely this workflow parallels the process of writing application code or scripts as an individual? This is what we mean when we talk about Terraform enabling infrastructure as code.

# WORKING AS A TEAM WITH TERRAFORM

When multiple practitioners collaborate on Terraform code, the core workflow (_Write, Plan, Apply_) adapts to mirror collaborative software development practices:

## 1. WRITE (BRANCHING & EXECUTION CONTEXT)

- **Branching Strategy:** Team members work in feature branches rather than pushing directly to main, allowing standard merge-conflict resolution for conflicting infrastructure changes.
    
- **Shift to Shared/CI Environments:** As infrastructure and sensitive variables (API keys, certificates) grow, running local plans becomes a security risk and an operational challenge. Teams often migrate executions to a shared Continuous Integration (CI) environment, which makes the feedback loop safer, though sometimes slower.
    

## 2. PLAN (PEER REVIEWS & SPECULATIVE PLANS)

- **Collaborative Reviews:** `terraform plan` output becomes a review artifact. Team members evaluate proposed changes during Pull Requests (PRs) to verify intent, assess risks, and catch errors early.
    
- **Automation & Timing:** Teams typically automate speculative plans to comment directly on PRs via CI. Beyond code review, this stage allows teams to assess operational impact and schedule merges to avoid unexpected outages or align with maintenance windows.
    

## 3. APPLY (FINAL VERIFICATION & EXECUTION)

- **Concrete Plan Execution:** Once a PR is merged into the shared branch, a fresh concrete plan is executed against the latest shared state to account for merge order or concurrent infrastructure drift.
    
- **Risk Assessment & Monitoring:** The team addresses pre-flight questions (e.g., service disruption risks, stakeholders to notify) and often monitors the live execution—either via shared screens or live CI/build logs.
    

# ENHANCEMENT VIA HCP TERRAFORM (TERRAFORM CLOUD / ENTERPRISE)

It is necessary to keep in mind how HCP Terraform streamlines team friction points:

- **Write:** Centralizes sensitive variables and remote state, allowing engineers to run remote speculative plans directly from the CLI without needing local secrets.
    
- **Plan:** Automatically triggers speculative plans on PR creation, posting clear status checks and deep links to full plan details.
    
- **Apply:** Provides structured run approvals, team discussion threads directly on the plan, and live streaming of the `apply` progress.
